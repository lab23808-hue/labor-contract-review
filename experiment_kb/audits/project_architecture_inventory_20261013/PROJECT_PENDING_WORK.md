**推荐主线：先完成"RAG排名退化归因与策略决策"这条线（即 A006 的后续：在 final_test 上独立验证方案C，然后决定是否纳入正式架构），再处理实验数据与DB管理，workplace场景规则优化、final_test标签核验、多合同类型扩展依次排在后面。**

1. 方案C（查询关键词路由）已经在 development 集上展示出全面优于当前方案A的结果（Recall@20从0.4991提升到0.5713），这是目前唯一一个已经有实验证据支持、且验证成本最低（只需要在90条final_test上跑一次，不需要重新设计实验）的改进点——"验证成本低、潜在收益已证实"决定了它应该排第一。

4. 多合同类型（租赁合同）扩展是最长周期的工作，且当前架构证据显示扩展路径本身是清晰的（见Part二.3），不存在"必须马上做否则后续返工"的紧迫性，可以放在最后。
